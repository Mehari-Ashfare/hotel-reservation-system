How a browser request turns into the app

Vite serves the HTML shell during development. The browser loads the entry module, React mounts into the page, and the app makes API requests to the backend when needed.

1. ViteReads vite.config.js and serves the project.
2. HTML shellindex.html provides the page and React mount point.
3. React entrysrc/main.jsx mounts the application into that point.
4. Applicationsrc/ contains the UI and its app behavior.
README.mdProject instructions

Objective: Explain the frontend to developers and provide the commands to install, start, build, and lint it.

How it works

  • It documents the React, Vite, and UI libraries used here.
  • It explains that the frontend and backend run as separate development servers.
  • It points to the API URL configuration and the backend CORS requirement.

When to update it

Update this file when setup commands, requirements, scripts, or important configuration change.

index.htmlBrowser document shell

Objective: Provide the one HTML document that Vite serves to the browser.

What is inside

  • The document metadata, page title, and mobile viewport setting.
  • <div id="root">, where React attaches the user interface.
  • A module script that loads /src/main.jsx.

Most application screens are rendered by React after startup rather than being written directly in this HTML file.

node_modules/Installed dependencies

Objective: Hold the local JavaScript packages required to run tools and application code.

How it works

Running npm install reads the package files and creates or updates this directory. Vite, React, Material UI, Axios, and other packages are resolved from here during local development and builds.

Do not edit or commit this folder

It is generated, often very large, and can be recreated with npm. Git normally ignores it.

package-lock.jsonDependency version lock

Objective: Record the exact dependency tree npm resolved, including transitive packages.

How it works

It helps different machines install a consistent set of package versions. npm updates it when dependency declarations change.

Keep it in Git. Avoid hand-editing it; use npm commands to change dependencies.

package.jsonProject manifest and commands

Objective: Declare the frontend package, its dependencies, and the npm scripts developers can run.

Scripts in this project

  • npm run dev starts Vite's development server.
  • npm run build creates production assets in dist/.
  • npm run preview locally serves the built output.
  • npm run lint runs ESLint.

Dependencies

dependencies lists packages used by the application. devDependencies lists development and build tools such as Vite and ESLint.

src/Application source

Objective: Contain the React application code loaded by index.html.

High-level role

The entry module is src/main.jsx. It mounts App into the HTML root. The application code then provides screens, navigation, shared state, API services, components, and styles.

This guide intentionally stops at the src/ folder. Its internal structure and files can be covered in the next guide.

vite.config.jsDevelopment and build configuration

Objective: Configure Vite, the React plugin, the development server, and source aliases.

Settings in this project

  • The React plugin supports React-specific development transforms.
  • The Vite server uses port 5173.
  • The src alias points to the source directory.
  • A proxy rule forwards relative /api requests to http://localhost:5000.
Proxy detail

The current Axios service uses the absolute URL http://localhost:5000/api, so those requests go straight to the backend and bypass Vite's proxy. The proxy applies if requests use a relative /api URL.

Install and run the frontend

Open a terminal in the frontend/ directory. Start the backend separately if the pages need database-backed API data.

npm install
npm run dev
npm run build

Vite prints the local address when it starts. This project configures port 5173; open http://localhost:5173 in your browser.
