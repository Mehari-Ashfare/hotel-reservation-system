Startup path, step by step

Each step hands control to the next layer. The first command is run from frontend/.

package.json → vite.config.js1. Start tools

npm run dev invokes the dev script in package.json, which starts Vite. Vite reads its configuration, starts on port 5173, and serves the frontend files.

index.html → main.jsx2. Mount React

Vite serves index.html. Its module script loads src/main.jsx. The entry imports global CSS, finds #root, and calls ReactDOM's createRoot(...).render(...).

main.jsx → App.jsx3. Set app-wide providers

App is rendered inside React.StrictMode. It wraps the app with AuthProvider, then sets up React Router and toast notifications. The route table selects what appears for each URL.

App.jsx → layouts/ + pages/4. Choose screen frame

The landing page is nested in PublicLayout. Operational pages are nested in DashboardLayout, which supplies a header, sidebar, and an Outlet for the selected page. The page components come from pages/.

Access-control detail

The route group is commented as protected, but the current DashboardLayout is a visual shell, not an authentication guard. Backend route authorization remains important for securing data.

pages/ → components/ + context/ + hooks/5. Compose interface

Pages combine reusable controls from components/, shared global styles from assets/styles/, and application state exposed by context or hooks. For example, the header and sidebar read the current user through useAuth.

What chooses and renders a page?

React Router matches the current browser URL to a route declared in App.jsx. The route renders a page, sometimes inside a layout. Layouts place the nested page in React Router's Outlet. React then draws the resulting component tree into the #root element.

Request and response path

A page can call a focused service such as GuestService or RoomService. Some screens call the shared Axios client directly. Both use services/api.js, whose request interceptor attaches a saved bearer token. The response interceptor clears stored session data and redirects to login on HTTP 401.

The frontend does not call backend controllers or database models directly. It sends HTTP requests to the Express API. Backend routes and handlers process those requests and return JSON; the frontend caller handles the result or error, updates local React state, and React re-renders affected components.

Folder responsibilities in the flow

pages/ owns route-level screens. components/ supplies reusable UI. layouts/ supplies page frames. context/ and hooks/ expose shared state and behavior. services/ talks to the API. assets/ supplies styles and images. routes/ and utils/ exist but are currently empty; active frontend routing is in App.jsx.

Important details from the current code

  • Vite proxy: vite.config.js defines a proxy for relative /api requests. The current Axios client uses the absolute URL http://localhost:5000/api, so these requests bypass the Vite proxy.
  • React Query: TanStack Query is listed as a dependency, but no QueryClientProvider or useQuery usage appears in the current source. The described request path uses Axios and component state.
  • Role menus: Sidebar menu items change based on the role in auth state. This controls what navigation is displayed, but backend authorization should enforce access to protected data and actions.

How the frontend connects to the backend

frontend/src/services/api.js configures the frontend HTTP client and the backend base URL. Frontend service modules use that client to send API requests.

On the backend, backend/app.js enables CORS and mounts API route groups under /api, such as /api/auth and /api/rooms. The backend address may be set in the frontend environment configuration.

In short: a frontend service calls api.js, the request reaches a route mounted by app.js, and the response returns to the frontend.
